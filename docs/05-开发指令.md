### 3.2 实现 services/tts-service.js

- `generateSpeech` 返回 Promise
- `playAudio` 返回 Promise(在音频播放结束时 resolve)
- `stopAudio` 立即停止

### 3.3 改造听写中页 ④

替换 Phase 2 的"假装播放"为真实播放:

```js
// pages/dictation/playing/index.js
async function playOneItem(item, settings) {
  this.setData({ isPlaying: true })
  const lang = getLang(item.type)

  for (let i = 0; i < settings.readCount; i++) {
    this.setData({ currentReadIndex: i })
    const { audioUrl } = await tts.generateSpeech(item.content, lang)
    await tts.playAudio(audioUrl)
    await sleep(200)
  }

  this.setData({ isPlaying: false })
  await sleep(settings.interval * 1000)
}
```

### 3.4 实现控制按钮的逻辑

- [ ] **重听:** 立即停止当前播放,重新读当前条目第 1 次(不消耗朗读次数)
- [ ] **暂停:** 设置 `isPaused = true`,听写循环检测到就 `await` 一个 promise,等取消暂停时 resolve
- [ ] **下一个:** 立即停止,跳到下一条

具体可用一个 state machine 思路实现:

```js
data: {
  isPaused: false,
  shouldSkip: false,
  shouldReplay: false
}

// 在循环中检测这些标记并做相应的处理
```

# ⚠️ 给 Claude Code 的特别提醒

**这些是常见错误,请避免:**

1. **不要自己改动产品规则**。如果觉得某条规则不合理,**先问**项目所有者,不要擅自改。

2. **不要把所有逻辑写在 page 里**。按 `04-服务集成.md` 的架构,业务逻辑分到 services/。

3. **不要直接调用微信底层 API**。所有外部依赖走 services/ 层。这样以后切换服务时业务代码不动。

4. **不要在前端写敏感信息**。云开发的密钥、第三方服务的 secret 都只能在云函数里用。

5. **不要写死配置**。云开发环境 ID、AppID 这些放在 `config.js` 或 `app.js` globalData,不要写死在多个地方。

6. **遇到决策点先问**。比如"列表为空时怎么显示""出错时弹窗还是 toast",PRD 里没写明确的,**问项目所有者**,不要自己拍板。

7. **每个 Phase 完成后让人工验证再继续**。不要 5 个 phase 一起做完一次性交付,容易出问题难定位。
