> 给开发者(包括 Claude Code)看的产品规则手册。**视觉怎么呈现请配合 `prototype_v9.html` 一起看。**

---

## 1. 产品定位

**书斋**是一个微信小程序工具集合,首期上线的核心工具是**单词听写**。

### 1.1 一句话定位

> 让家长和孩子在家就能完成英语和中文的听写练习,AI 自动判分,错词自动收藏,告别"喂饭式辅导"。

### 1.2 用户画像

- **主要用户:**辅导孩子学习的家长(小学到初中阶段)
- **次要用户:**自主学习的孩子(中高年级)
- **使用场景:**老师布置听写作业 → 家长手动录入或拍照导入 → 孩子戴耳机听写 → 拍照判分 → 错词复习

### 1.3 产品哲学(请认真理解)

| 原则 | 含义 | 反例(开发时不要这样) |
|---|---|---|
| **极简** | 只做听写,不做学习/记忆/翻译等延伸功能 | 不要加单词释义、不要加跟读评分、不要加排行榜 |
| **零摩擦** | 用户输入到听完,操作越少越好 | 不要加确认弹窗、不要加新手引导、不要强制注册 |
| **概念统一** | 一个对象只有一个名字 | 不要并存"错词本"和"单词本",只有"单词本",错词是它的一个筛选视图 |
| **后台跑** | 流程能自动跑就别让用户操作 | 听写中间隔时间到了自动下一题,不要让用户按"下一个" |

## 3. 内容类型自动识别规则

用户在输入框输入任意文本后,**系统自动判断**它的类型并选择对应 TTS 语种。**不让用户手动切换。**

### 3.1 判定逻辑(伪代码)

```
function detectType(text):
    text = text.strip()
    has_chinese = 文本中包含任何汉字字符
    has_space   = 文本中包含空格

    if has_chinese:
        if 文本长度 > 6 或 包含中文标点:
            return 'cn_sentence'   # 中文句子
        else:
            return 'cn_word'       # 中文词
    else:
        if has_space:
            return 'en_sentence'   # 英文句子
        else:
            return 'en_word'       # 英文单词
```

### 3.2 边界情况

| 输入 | 判定 | TTS 语种 |
|---|---|---|
| `apple` | `en_word` | en_US |
| `don't` | `en_word` | en_US(撇号不算空格) |
| `good morning` | `en_sentence` | en_US |
| `I like apples.` | `en_sentence` | en_US |
| `苹果` | `cn_word` | zh_CN |
| `床` | `cn_word` | zh_CN(单字也算词) |
| `床前明月光,疑是地上霜。` | `cn_sentence` | zh_CN |
| `我喜欢 apple` | `cn_sentence` | zh_CN(含中文按中文处理) |
| `1234` | `en_word` | en_US(默认走英文) |

### 3.3 UI 反馈

- 用户每打一个字,**输入框下方实时显示**当前判定的类型 tag(`EN 句` / `中` 等),让用户能即时确认
- 列表里每一条左边挂彩色 tag,方便后续辨识

## 4. 判分规则(核心业务逻辑)

判分发生在**孩子写完答卷后**,系统拿到答卷图片,与"听写清单"比对。

### 4.1 判分模型:**清单交集 + 规范化匹配**

- **数据源 A:** 听写清单(用户录入的内容,标准答案)
- **数据源 B:** 答卷 OCR 识别结果(孩子手写的内容)
- **匹配方式:** 对 A 中的每一条,看是否能在 B 中找到匹配项

### 4.2 规范化处理(匹配前做)

匹配前对**双方**做以下清洗:

1. 转小写
2. 删除所有标点符号(英文 `.,!?;:'"`/中文 `,。!?;:""''`)
3. 多个连续空格压缩成一个,首尾空格删除

### 4.3 匹配规则示例

| 标准答案(A) | 答卷识别(B) | 匹配结果 |
|---|---|---|
| `apple` | `Apple` | ✓ 匹配(大小写不计) |
| `apple` | `apples` | ✗ 不匹配(字母不同) |
| `apple` | `oraneg` | ✗ 不匹配 |
| `床前明月光` | `床前明月光,` | ✓ 匹配(标点不计) |
| `I like apples.` | `i like apples` | ✓ 匹配 |
| `I like apples.` | `I like aples very much` | ✗ 不匹配(整句字母不同) |

### 4.4 句子内的词级 diff(给好的反馈)

如果整句**不匹配**,系统进一步做**词级 diff**(仅英文句子):

```
标准: I like apples very much
答卷: I like aples very much

词级 diff 结果:
  - 'I'      ✓
  - 'like'   ✓
  - 'apples' ✗ (答卷写成 'aples')
  - 'very'   ✓
  - 'much'   ✓

UI 展示: I like [aples] very much.   ← aples 标红+删除线
        正确: apples
```

**中文句子**只做整句对错判定,不做字级 diff(中文 OCR 准确率低,做太精细反而显得不准)。

### 4.5 顺序无关

判分**不要求**答卷上的顺序与清单一致。孩子可以乱序写。**只要清单里有 + 答卷上有,就算对。**

### 4.6 跳过的内容怎么处理

- 听写时按"下一个"跳过的条目,**仍然进入判分清单**
- 答卷上能找到 → 算对
- 答卷上找不到 → 算错

### 4.7 重复条目的处理

录入时如果检测到重复(规范化后相同),**禁止重复添加**,Toast 提示"已存在"。从源头避免判分时的歧义。

## 5. TTS(语音合成)规则

### 5.1 主方案:微信同声传译插件

- 插件名:`WechatSI`
- AppID:`wx069ba97219f66d99`
- 调用:`plugin.textToSpeech({ lang, content, tts: true })`
- 单次合成限制:1000 字节

### 5.2 语种映射

| 内容类型 | TTS lang 参数 |
|---|---|
| `en_word` / `en_sentence` | `en_US` |
| `cn_word` / `cn_sentence` | `zh_CN` |

### 5.3 朗读流程

```
对清单中的每一条内容(顺序):
  for 次数 in 1..朗读次数(默认 2):
    1. 调 TTS 生成音频
    2. 播放音频
    3. 播放结束后等 200ms(避免连读黏在一起)
  等待"间隔时间"(默认 5 秒)
  进入下一条
```

### 5.4 自动连播

- 一条读完后**自动**等"间隔时间"再读下一条,**用户不需要操作**
- 间隔等待期间不做任何 UI 状态切换(对用户透明),仅水波纹动画停止
- 用户按"重听" → 立即重播当前条目(不消耗朗读次数)
- 用户按"下一个" → 立即跳到下一条(当前条目可能未读完)
- 用户按"暂停" → 整个流程冻结(包括正在播放的音频),再按变继续

### 5.5 错误处理

- TTS 调用失败:Toast "网络异常,请重试",停留在当前条目
- 音频播放失败:同上

### 5.6 备用方案(MVP 不实现,留架构口子)

代码层把 TTS 抽象成 `tts-service` 模块,导出统一的 `speak(text, lang)` 接口。  
后期切换为腾讯云 TTS 时,只需替换 `tts-service` 内部实现,业务代码不动。

参考 `04-服务集成.md` 第 2 节"TTS 切换备用方案"。

## 6. OCR(图片文字识别)规则

OCR 用于两个场景:**录入听写内容**(可选)、**判分答卷**(可选)。

### 6.1 主方案:微信通用印刷体识别

- 接口:云函数中调用 `cloud.openapi.ocr.printedText`
- 配额:免费 100 次/天/小程序
- 能力:支持**印刷体**中英文识别(对手写体识别效果一般,但可用)

### 6.2 调用流程

```
小程序前端                     云函数                     微信 OCR
─────────────                ─────────                  ──────────
1. 选图 wx.chooseImage
2. 上传到云存储             →  上传完成,返回 fileID
3. 调用 callFunction         →  接收 fileID
                                4. 调用 cloud.openapi.ocr.printedText  → 识别
                                5. 返回识别结果        ←  返回 OCR 结果
6. 拿到结果 → 处理 / 显示
```

### 6.3 结果后处理

OCR 返回的是若干"文字块",需要后处理:

**录入场景**(用户拍听写清单):
- 把每个文字块当作一个听写条目
- 对每个条目调用第 3 节的内容类型判定
- UI 展示时:可疑结果(包含数字、特殊字符等)用黄底标出,提示用户核对

**判分场景**(用户拍答卷):
- 把所有文字块合并成一个大字符串
- 对每条清单内容,在这个字符串里搜索是否存在(规范化后)
- 注意:答卷上可能有"序号""1. apple"等,后处理时去掉数字和点号开头

### 6.4 错误处理

- OCR 调用失败 → 引导用户改用"手动核对"
- OCR 返回空结果 → 同上
- 配额用完(每天 100 次) → 提示"今日识别次数已用完,请用手动核对"

### 6.5 备用方案(MVP 不实现,留架构口子)

同 TTS,抽象成 `ocr-service` 模块,导出 `recognize(fileID)` 接口。  
后期切换为腾讯云手写体 OCR(更适合识别孩子手写答卷)时,只换内部实现。

参考 `04-服务集成.md` 第 3 节"OCR 切换备用方案"。

## 7. 手动核对模式(OCR 兜底)

当 OCR 不可用或不准时,用户可以**逐题翻牌**人工核对。

### 7.1 触发场景

1. 听写完成后,用户在 ⑤号页面选择"改用手动核对"
2. OCR 调用失败时,系统自动引导切换

### 7.2 交互流程

逐题展示听写清单中的内容,家长比对答卷后点击:
- ✓ 写对了 → 此条标记为正确
- ✗ 写错了 → 此条标记为错误

全部核对完后,跳到判分结果页(跟拍照判分用同一个页面)。

## 8. 单词本(历史记录)

### 8.1 数据结构

每次完整听写完成(进入判分页那一刻),记录一条 `session`:
- 包含该次的所有条目和判分结果
- 按日期分组展示

### 8.2 单词本页面行为

- **底部 Tab 切换:**与"听写"主页平级
- **筛选 Tab:**"全部记录" / "仅错词"(单词本内部过滤)
- **按日期分组:**今天、昨天、更早,每组展示概要(`5 / 6 正确`)
- **"用错词重新听写"按钮:**底部,把所有错过的条目作为新的听写清单(`仅错词`筛选时显示)

### 8.3 数据保留策略

- MVP 阶段:**永久保留**,云数据库存
- 不主动清理,直到用户量上来再考虑(比如保留近 90 天)

## 9. 用户与登录

### 9.1 登录方式

- 进入小程序时,**首次自动调用** `wx.login()` 获取 code → 云函数换 openid
- 不需要弹"授权""注册"等任何窗口(MVP 不要任何登录摩擦)
- 后续所有数据用 openid 标识归属

### 9.2 多设备/多账号

- MVP 阶段:同一微信号在多设备登录,数据共享(都是同一个 openid)
- 不支持微信号 A 共享数据给微信号 B(不需要这个功能)

## 12. 数据约束与边界

### 12.1 数量限制

| 项目 | 限制 |
|---|---|
| 单条内容长度 | 最少 1 字符,最多 200 字符 |
| 单次听写清单条目数 | 最多 50 条(避免一次太久) |
| 单词本历史保留 | 不限(MVP 阶段) |

### 12.2 性能要求

- 主页打开 → 看到内容:< 1 秒
- 输入框输入 → 类型识别反馈:即时(< 100ms)
- TTS 调用 → 开始播放:< 2 秒
- OCR 调用 → 拿到结果:< 10 秒(超时提示用户)
