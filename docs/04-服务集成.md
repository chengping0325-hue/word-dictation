# 单词听写喵 · 服务集成

> 给开发者(包括 Claude Code)看的外部服务调用规范。**所有外部依赖都封装在 `services/` 目录,业务代码不直接调用底层 API**。

---

## 1. 服务架构总览

```
业务代码(pages/)
     │
     ▼
services/   ← 抽象层(本文档定义的接口)
     │
     ├── tts-service.js   ──→  同传插件 / 腾讯云 TTS(备用)
     ├── ocr-service.js   ──→  微信印刷体 OCR / 腾讯云手写体 OCR(备用)
     ├── grading-service.js  ──→  纯前端逻辑
     └── type-detector.js    ──→  纯前端逻辑
```

**原则:**业务代码只调 `services/*` 的接口,不直接调微信 API 或云函数。这样后期切换服务,只改 `services/` 内部实现,**业务代码一行不用动**。

## 2. TTS 服务(`services/tts-service.js`)

### 2.1 对外接口

```js
/**
 * 朗读一段文本
 * @param {string} text  要朗读的内容
 * @param {string} lang  语种:'en_US' | 'zh_CN'
 * @returns {Promise<{audioUrl, duration}>}  resolve 时表示音频已生成,失败 reject
 */
export function generateSpeech(text, lang) { ... }

/**
 * 立即播放已生成的音频
 * @param {string} audioUrl
 * @returns {Promise<void>}  resolve 时表示播放完成
 */
export function playAudio(audioUrl) { ... }

/**
 * 停止当前播放(暂停或切换时调)
 */
export function stopAudio() { ... }
```

### 2.2 主实现:同传插件

```js
// services/tts-service.js (主实现)

const plugin = requirePlugin('WechatSI')
let currentAudioContext = null

export function generateSpeech(text, lang) {
  return new Promise((resolve, reject) => {
    plugin.textToSpeech({
      lang: lang,       // 'en_US' 或 'zh_CN'
      tts: true,
      content: text,
      success(res) {
        // res.filename 是音频临时路径
        resolve({ audioUrl: res.filename })
      },
      fail(err) {
        console.error('[TTS] 合成失败:', err)
        reject(err)
      }
    })
  })
}

export function playAudio(audioUrl) {
  return new Promise((resolve, reject) => {
    stopAudio()  // 先停掉前一次的

    const ctx = wx.createInnerAudioContext()
    currentAudioContext = ctx
    ctx.src = audioUrl
    ctx.onEnded(() => {
      ctx.destroy()
      currentAudioContext = null
      resolve()
    })
    ctx.onError((err) => {
      ctx.destroy()
      currentAudioContext = null
      reject(err)
    })
    ctx.play()
  })
}

export function stopAudio() {
  if (currentAudioContext) {
    currentAudioContext.stop()
    currentAudioContext.destroy()
    currentAudioContext = null
  }
}
```

### 2.3 备用方案:腾讯云 TTS

当业务量上来,或者需要支持个人主体(同传插件不支持),切换到腾讯云 TTS:

```js
// services/tts-service.js (备用实现)

import { callCloudFunction } from '../utils/cloud'

export function generateSpeech(text, lang) {
  // 调用云函数,云函数内调腾讯云 SDK
  return callCloudFunction('tts', {
    text,
    lang: lang === 'en_US' ? 'en' : 'zh'   // 腾讯云的 lang 编码不同
  }).then(res => ({
    audioUrl: res.audioBase64   // 或 audioUrl,看云函数返回
  }))
}

// playAudio 和 stopAudio 不变,因为它们处理的是音频播放,跟谁合成无关
```

切换时需要做的事:
1. 在腾讯云控制台开通 TTS 服务,获取 SecretId / SecretKey
2. 写云函数 `cloudfunctions/tts/`,内部调腾讯云 SDK
3. **替换 `services/tts-service.js` 内的 `generateSpeech` 实现**
4. 业务代码完全不动

### 2.4 关键约束(主方案)

- 单次合成内容**最多 1000 字节**(中文约 333 字,英文约 1000 字符) —— MVP 阶段够用,不会触发
- 同传插件**不支持个人主体小程序**,如果小程序是个人注册的,主方案无法用,直接走备用方案
- TTS 生成的音频是临时文件,**重启小程序后失效**,不要长期缓存

### 2.5 业务代码怎么用

```js
// pages/dictation/playing/index.js
import * as tts from '../../../services/tts-service'

async function readOneItem(item, settings) {
  const lang = (item.type.startsWith('en')) ? 'en_US' : 'zh_CN'

  for (let i = 0; i < settings.readCount; i++) {
    const { audioUrl } = await tts.generateSpeech(item.content, lang)
    await tts.playAudio(audioUrl)
    await sleep(200)  // 多次之间小间隔
  }

  // 等间隔时间
  await sleep(settings.interval * 1000)
}
```

## 2.6 音频播放选项(`wx.setInnerAudioOption`)

### 2.6.1 问题背景

iOS 上 `InnerAudioContext` **默认跟随手机物理静音键**。用户把手机拨到静音后,
听写流程会「看起来在正常播放」但**全程没有任何声音**,也没有任何错误提示——
用户只会以为 App 卡死了。

安卓不受影响(WebView 音频默认不跟随静音键),所以这个问题只在 iOS 真机上暴露,
容易在开发者工具里漏测。

### 2.6.2 解决方案

在 `app.js` 的 `onLaunch` 里做**全局**配置:

```js
if (wx.setInnerAudioOption) {
  wx.setInnerAudioOption({
    obeyMuteSwitch: false,   // 关键:iOS 静音模式下照常出声
    mixWithOther: true,       // 保留混播意图(当前 speakerOn 为 true 时不生效)
    speakerOn: true           // 走扬声器
  })
}
```

### 2.6.3 三个参数的实际行为

| 参数 | 含义 | 本项目取值与原因 |
|------|------|------------------|
| `obeyMuteSwitch` | 是否遵循静音开关(仅 iOS 生效) | **false**。这是解决静音无声的唯一关键项 |
| `speakerOn` | true 扬声器 / false 听筒 | **true**。听写场景优先保证声音外放清晰 |
| `mixWithOther` | 是否与其他音频混播 | true。**但注意微信规定:`speakerOn` 为 true 时会忽略此参数,强制与其他音频互斥** |

> **产品取舍说明**:`mixWithOther` 与 `speakerOn` 在微信里是互斥的,没有
> 「外放 + 不打断其他音频」的组合。听写场景需要外放清晰,因此接受
> 「用户手机正在放音乐时会被短暂打断」这一行为。代码里仍写入 `mixWithOther: true`,
> 保留意图,若未来微信放开限制则自动生效。

### 2.6.4 版本兼容(重要)

- `wx.setInnerAudioOption` 需要**基础库 ≥ 2.3.0**,低版本需判空(`if (wx.setInnerAudioOption)`)
- **基础库 2.3.0 起,实例级 `ctx.obeyMuteSwitch = false` 已失效**,官方要求统一用全局 API
- 但 2.3.0 之前的低版本客户端上,唯一能让 iOS 静音出声的方式就是设置实例属性。
  因此 `tts-service.js` 的 `playAudio()` 里也做了一次实例级赋值(包在 try/catch 里),
  低版本靠实例属性生效,新版本靠全局配置——两个都设,互不冲突。

### 2.6.5 验证方法

1. iPhone 真机打开小程序
2. **把侧边物理静音键拨到静音状态**
3. 进入听写流程,确认能听到朗读声

> 开发者工具的模拟器无法模拟静音键,这一步**必须在真机上做**。

## 2.7 iOS 静音开关:为什么光靠 `setInnerAudioOption` 不够

### 2.7.1 问题现象

iOS 真机把手机拨到静音后启动听写流程:

- 不静音 → 朗读正常
- 静音 → **全程无声**,界面却正常在走(进度条在动、朗读计数在跳),没有任何错误提示

用户只会以为 App 卡死了。安卓不受影响(WebView 音频默认不跟随静音键),
所以这个问题**只在 iOS 真机暴露**,开发者工具模拟器完全测不出来。

### 2.7.2 只配 `setInnerAudioOption` 为什么可能无效

第一版修复只做了 `wx.setInnerAudioOption({ obeyMuteSwitch: false })`,
放在 `app.js` 的 `onLaunch` 里(方案本身没错,官方文档也是这么推荐的),
但真机测试依然静音无声。

排查后确认了**两个被忽略的前提**:

**① iOS 的音频会话类别在「首次 play()」时才确定**

`AVAudioSession` 有好几个类别,决定它是否受静音键压制:

| 类别 | 静音键影响 | 触发条件 |
|------|------------|---------|
| `ambient` | **受压制** | 默认值 |
| `playback` | 不受压制 | 首次播放发生在**用户手势的同步栈**内 |

关键在于 iOS 的 WebKit 策略:**音频必须在用户主动交互的回调中首次播放**。
如果首次 `play()` 不在手势栈内(例如 `navigateTo` 之后在 `onLoad` 里
等云函数返回再播),系统会按 `ambient` 激活会话 → 静音键生效。

本项目原来的调用链正好踩中:

```
用户点击「开始听写」          ← 手势在这里
  → wx.navigateTo()            ← 手势栈到此断开
  → playing 页 onLoad()
  → await tts.generateSpeech()  ← 异步云函数 + 写文件,1-2 秒
  → await tts.playAudio() → ctx.play()   ← 首次 play 不在手势内 → ambient
```

**② 每次播放都 `createInnerAudioContext()` 新建实例**

新实例可能重新走一次「非手势激活」路径,再次落回 `ambient`。
必须复用同一实例,让它继承已激活的会话类别。

### 2.7.3 解决方案

**第一步:在用户手势内用静音文件唤醒会话**

`tts-service.js` 新增 `unlockAudio()`,在主页「开始听写」的手势回调里
**同步调用**(必须早于 `navigateTo`):

```js
// pages/dictation/index/index.js
onStart() {
  // ...
  tts.unlockAudio()          // ← 手势同步栈内
  wx.navigateTo({ url: '/pages/dictation/playing/index' })
}
```

`unlockAudio()` 播放一个 80ms 的静音 mp3,把人耳听不见的声音送进扬声器,
让 iOS 以 `playback` 类别激活音频会话。之后所有播放都继承这个类别。

**第二步:复用同一个 InnerAudioContext 实例**

```js
let sharedContext = null   // 模块级共享

function playAudio(audioUrl) {
  if (!sharedContext) {
    sharedContext = wx.createInnerAudioContext()
    try { sharedContext.obeyMuteSwitch = false } catch (e) {}
  }
  // ...
}
```

**第三步:停止播放时只 `stop()`,不 `destroy()`**

`destroy()` 会把已激活的会话类别一起丢掉,下次播放又得重新走一遍
「非手势激活」路径,又落回 `ambient`。所以 `_finalize` / `_internalStop`
都只调 `stop()`,`destroy()` 收进 `tts.destroy()`,仅在需要彻底重置时使用。

### 2.7.4 静音文件的硬性要求

`miniprogram/assets/silence.mp3`(748 字节):

| 要求 | 原因 | 本项目 |
|------|------|--------|
| 必须是**真实音频文件**(不能是空文件) | 空文件不会触发音频会话激活 | 80ms 正弦静音 |
| 时长 > 0 | 同上 | 80ms |
| 必须是 **MP3** 格式 | iOS 的 XWeb 内核对 AAC 支持不稳定 | MP3 |
| 采样率 **44100Hz** | 同上 | 44100Hz |
| 体积尽量小 | 主包上限 2MB | 748 字节 |

### 2.7.5 验证方法

1. **iPhone 真机**打开小程序
2. **把侧边物理静音键拨到静音**
3. 点「开始听写」,确认能听到朗读声

Console 应能看到 `[tts-service] 音频会话已唤醒`。

> 开发者工具模拟器无法模拟静音键,这一步**必须在真机上做**。
> 安卓不用测(`obeyMuteSwitch` 只在 iOS 生效)。

### 2.7.6 回归测试

`miniprogram/services/tts-service.test.js` 固化了以下约定,防止后续误改:

- 静音文件存在、< 5KB、是 MP3、44100Hz
- `unlockAudio` 导出且引用了 `/assets/silence.mp3`、`volume = 0`
- `playAudio` 复用 `sharedContext`
- `_finalize` / `_internalStop` 里不出现 `destroy()`
- 主页 `onStart` 调用了 `tts.unlockAudio()`,且在 `wx.navigateTo` **之前**

### 3.2 主实现:微信通用印刷体识别

#### 3.2.1 云函数 `cloudfunctions/ocr/`

```js
// cloudfunctions/ocr/index.js

const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })

exports.main = async (event) => {
  const { fileID } = event

  // 先把云存储 fileID 转成临时 URL
  const fileRes = await cloud.getTempFileURL({ fileList: [fileID] })
  const imageUrl = fileRes.fileList[0].tempFileURL

  try {
    const res = await cloud.openapi.ocr.printedText({
      type: 'photo',
      imgUrl: imageUrl
    })
    // res.items 是一个数组,每项是 { text, pos, ... }
    return {
      success: true,
      items: res.items.map(i => i.text)
    }
  } catch (err) {
    console.error('[OCR] 失败:', err)
    return {
      success: false,
      error: err.errMsg || '识别失败'
    }
  }
}
```

#### 3.2.3 服务层封装

```js
// services/ocr-service.js (主实现)

import { callCloudFunction } from '../utils/cloud'

export async function recognize(fileID) {
  const res = await callCloudFunction('ocr', { fileID })

  if (!res.success) {
    throw new Error(res.error || 'OCR 识别失败')
  }

  // 进一步后处理:去掉序号、空字符串
  const items = res.items
    .map(text => text.replace(/^\d+[.、)\s]+/, '').trim())  // 去序号
    .filter(text => text.length > 0)

  return { items }
}
```

## 4. 判分服务(`services/grading-service.js`)

**纯前端逻辑,不依赖任何外部服务。** 主要做规范化、匹配、词级 diff。

### 4.1 对外接口

```js
/**
 * 规范化一段文本(用于判分时的比对)

 * @returns {string}

/**
 * 判分整次听写会话
 * @param {Array<Item>} list           听写清单(标准答案)
 * @param {Array<string>} ocrTexts     OCR 识别的文字块数组
 * @returns {SessionResult}            { score, items }
 */
export function gradeSession(list, ocrTexts) { ... }

/**
 * 对一对内容做词级 diff(仅英文句子用)
 * @param {string} standard
 * @param {string} userAnswer
 * @returns {WordDiff[]}
 */
export function wordLevelDiff(standard, userAnswer) { ... }
```

### 4.2 normalize 实现

```js
export function normalize(text) {
  return text
    .toLowerCase()                                            // 转小写
    .replace(/[.,!?;:'"()。,!?;:""''《》【】]/g, '')           // 去标点(中英)
    .replace(/\s+/g, ' ')                                     // 多空格压缩
    .trim()                                                   // 去首尾
}
```

### 4.3 gradeSession 实现思路

```js
export function gradeSession(list, ocrTexts) {
  // 1. 把 OCR 的所有文字块合并成一个大字符串
  const fullText = ocrTexts.join(' ')
  const normalizedFull = normalize(fullText)

  // 2. 对清单中每条做判定
  const items = list.map(item => {
    const normalizedStandard = normalize(item.content)

    // 在 normalizedFull 里找是否包含 normalizedStandard
    const isCorrect = normalizedFull.includes(normalizedStandard)

    const result = {
      content: item.content,
      type: item.type,
      userAnswer: findUserAnswer(item, ocrTexts),  // 找到对应的用户答案(用于展示)
      isCorrect
    }

    // 英文句子且错误 → 做词级 diff
    if (!isCorrect && item.type === 'en_sentence' && result.userAnswer) {
      result.wordDiff = wordLevelDiff(item.content, result.userAnswer)
    }

    return result
  })

  // 3. 计算总分
  const correct = items.filter(i => i.isCorrect).length
  const total = items.length

  return {
    score: { correct, total, rate: total > 0 ? correct / total : 0 },
    items
  }
}

function findUserAnswer(item, ocrTexts) {
  // 简单实现:找到一个跟 item.content 最相似的 OCR 文字块
  // 用编辑距离或 Jaccard 相似度都可以
  const normalizedStandard = normalize(item.content)
  let best = null
  let bestScore = 0
  for (const text of ocrTexts) {
    const normalized = normalize(text)
    const score = similarity(normalized, normalizedStandard)  // 实现一个相似度函数
    if (score > bestScore) {
      best = text
      bestScore = score
    }
  }
  return bestScore > 0.3 ? best : null  // 太低就当没找到
}
```

### 4.4 wordLevelDiff 实现

英文句子按空格分词,做对齐:

```js
export function wordLevelDiff(standard, userAnswer) {
  const stdWords = standard.toLowerCase().replace(/[.,!?;:]/g, '').split(/\s+/)
  const usrWords = userAnswer.toLowerCase().replace(/[.,!?;:]/g, '').split(/\s+/)

  // 用 LCS(最长公共子序列)算法做对齐
  // 简单版:逐位置比较
  const result = []
  const maxLen = Math.max(stdWords.length, usrWords.length)

  for (let i = 0; i < maxLen; i++) {
    const stdWord = stdWords[i]
    const usrWord = usrWords[i]

    if (stdWord && usrWord) {
      if (stdWord === usrWord) {
        result.push({ word: usrWord, ok: true })
      } else {
        result.push({ word: usrWord, ok: false, expected: stdWord })
      }
    } else if (stdWord) {
      result.push({ word: '', ok: false, expected: stdWord, missing: true })
    } else {
      result.push({ word: usrWord, ok: false, extra: true })
    }
  }

  return result
}
```

> **注意:** 实际开发时建议引入 `diff` 这种成熟库做对齐,逐位置比较会在"多/少一个词"时整体错位。MVP 可以先用简单版。

## 5. 类型识别服务(`services/type-detector.js`)

### 5.1 对外接口

```js
/**
 * 判定一段内容的类型
 * @param {string} text
 * @returns {'en_word' | 'cn_word' | 'en_sentence' | 'cn_sentence'}
 */
export function detectType(text) { ... }

/**
 * 获取类型对应的 TTS 语种
 * @param {string} type
 * @returns {'en_US' | 'zh_CN'}
 */
export function getLang(type) {
  return type.startsWith('en') ? 'en_US' : 'zh_CN'
}
```

### 5.2 实现

```js
export function detectType(text) {
  const trimmed = text.trim()
  const hasChinese = /[\u4e00-\u9fa5]/.test(trimmed)
  const hasSpace = /\s/.test(trimmed)
  const hasChinesePunct = /[,。!?;:""''《》【】]/.test(trimmed)

  if (hasChinese) {
    if (trimmed.length > 6 || hasChinesePunct) {
      return 'cn_sentence'
    } else {
      return 'cn_word'
    }
  } else {
    if (hasSpace) {
      return 'en_sentence'
    } else {
      return 'en_word'
    }
  }
}
```

### 6.1 调用时机

`app.js` 的 `onLaunch` 里:

```js
App({
  async onLaunch() {
    wx.cloud.init({ env: 'YOUR-ENV-ID' })

    // 首次启动获取 openid
    const cachedOpenid = wx.getStorageSync('openid')
    if (cachedOpenid) {
      this.globalData.openid = cachedOpenid
    } else {
      const res = await wx.cloud.callFunction({ name: 'login' })
      this.globalData.openid = res.result.openid
      wx.setStorageSync('openid', res.result.openid)
    }

    // 创建/更新 user 记录
    await this.upsertUser()
  },

  async upsertUser() {
    const db = wx.cloud.database()
    const { data } = await db.collection('users').where({}).get()
    if (data.length === 0) {
      await db.collection('users').add({
        data: {
          createdAt: db.serverDate(),
          lastActiveAt: db.serverDate()
        }
      })
    } else {
      await db.collection('users').doc(data[0]._id).update({
        data: { lastActiveAt: db.serverDate() }
      })
    }
  },

  globalData: {
    openid: '',
    currentDictation: null,
    currentResult: null,
    pendingOcrResult: null
  }
})
```

## 7. 云函数 `session/`(听写会话存取)

### 7.1 用途

虽然前端可以直接用云数据库 SDK 操作,但**写入 session 时建议走云函数**,以便:
- 服务端校验数据合法性
- 未来加业务规则(比如"每天最多保存 100 条")

### 7.2 实现

```js
// cloudfunctions/session/index.js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const db = cloud.database()

exports.main = async (event, context) => {
  const { action, data } = event
  const wxContext = cloud.getWXContext()

  if (action === 'save') {
    // 保存一次听写
    return await db.collection('sessions').add({
      data: {
        _openid: wxContext.OPENID,
        createdAt: db.serverDate(),
        mode: data.mode,
        settings: data.settings,
        score: data.score,
        items: data.items
      }
    })
  }

  // 读 session 推荐直接前端 SDK 调,效率更高
}
```

## 9. 错误处理统一约定

所有 service 抛错时,业务代码用 `try/catch` 包住,并向用户展示友好提示:

```js
try {
  const result = await ocr.recognize(fileID)
} catch (err) {
  wx.showToast({
    title: '识别失败,请重试',
    icon: 'none',
    duration: 2000
  })
  // 引导兜底方案
  setTimeout(() => {
    wx.showModal({
      title: '换用手动核对?',
      success(res) {
        if (res.confirm) {
          wx.redirectTo({ url: '/pages/dictation/manual-check/index' })
        }
      }
    })
  }, 2000)
}
```
