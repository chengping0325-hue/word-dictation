## 4. 跳转代码与参数传递

### 4.1 小程序启动入口

`pages/dictation/index/index` 位于 `app.json` 的 `pages` 数组首位。冷启动、分享卡片和重新进入小程序均直接到达听写主页,根页面不显示返回箭头。

### 4.2 从主页进入听写中

```js
// pages/dictation/index/index.js
// 把清单存到全局状态(getApp().globalData)或本地缓存,听写中页面读取
const app = getApp()
app.globalData.currentDictation = {
  list: [...],          // 清单数组
  readCount: 2,         // 朗读次数
  interval: 5           // 间隔秒数
}
wx.navigateTo({ url: '/pages/dictation/playing/index' })
```

### 4.3 听写中 → 听写完成

```js
// pages/dictation/playing/index.js (清单全部读完时)
wx.redirectTo({ url: '/pages/dictation/finished/index' })
// 注意用 redirectTo 而不是 navigateTo,避免用户返回到"正在听写"
```

### 4.4 听写完成 → 判分

```js
// 用户选择拍照判分
wx.chooseImage({...}).then(...).then(fileID => {
  wx.navigateTo({
    url: `/pages/dictation/grading/index?fileID=${encodeURIComponent(fileID)}`
  })
})

// 用户选择手动核对
wx.navigateTo({ url: '/pages/dictation/manual-check/index' })
```

### 4.5 判分中 → 判分结果

```js
// pages/dictation/grading/index.js (OCR + 判分完成后)
const app = getApp()
app.globalData.currentResult = {
  score: { correct: 4, total: 6 },
  items: [...]   // 每条的判分明细
}
wx.redirectTo({ url: '/pages/dictation/result/index' })
```

### 4.10 问题反馈页(长按二维码加客服微信)

**定位**:把反馈从「用户不知道去哪找开发者」变成「长按二维码就能加到人」。

**页面结构**:

```
[原生导航栏:问题反馈]

  ┌───────────────────────────┐
  │      <二维码图片>            │  ← show-menu-by-longpress
  │  长按识别二维码,添加客服微信    │
  │    遇到问题、想要建议,直接告诉我们 │
  └───────────────────────────┘

(整张卡片居中于屏幕)
```

**关键实现点**:

1. **必须显式写 `show-menu-by-longpress="{{true}}"`**
   该属性默认值是 `false`,不加的话长按只会弹「保存图片」,识别不出码。

2. **二维码必须是包内本地路径或合法 HTTPS 地址**
   `tempFilePath` 会被小程序运行时安全策略**硬性拦截**,即使设了 `show-menu-by-longpress`
   也静默忽略。本项目用包内路径 `miniprogram/assets/feedback-qrcode.png`,无需配域名。

3. **基础库要求 ≥ 2.18.0**
   官方文档「支持长按识别的码」表格列出:小程序码、微信个人码、**企业微信个人码**、
   普通群码、互通群码、公众号二维码,均需 2.18.0。
   本项目 `project.config.json` 的 `libVersion` 是 3.15.2,满足要求。

4. **页面只保留二维码,不做额外兜底**
   长按识别在低版本基础库上不可用(需 iOS ≥ 8.0.8 / 安卓 ≥ 8.0.7),
   部分用户也不知道要长按。当前版本接受这个缺口:页面保持极简,
   只呈现「长按识别二维码,添加客服微信」一个明确动作。

   > 早期版本曾加过「复制客服邮箱」卡片作为兜底,后按产品决策移除。
   > 若日后要补回,注意用户加的是**企业微信**,拿不到也不需要个人微信号,
   > 邮箱是与 `docs/PRIVACY.md` 一致的渠道。

5. **短按二维码不做任何响应**
   误触短按若无反馈,用户会以为长按识别坏了。

**图片规格**(当前已就位):

| 项 | 值 |
|----|-----|
| 内容 | 企业微信「联系我」**渠道活码**,`https://work.weixin.qq.com/u/vcd...` |
| 尺寸 | 512 × 512(从原图 319×489 裁切 + LANCZOS 放大) |
| 体积 | 36KB(8bit 调色板量化,原裁切图 132KB) |
| 静区 | 四周 16px 白边 |

> **静区是硬要求**:实测紧贴模块裁切(0px 静区)时 OpenCV 解码**失败**,
> 留 8px 白边即成功。裁切时务必保留原图自带的白色边缘,不要贴边。

> **活码的好处**:后台可随时更换接待成员 / 修改欢迎语,
> **二维码图片不用变,不需要重新发版**。这比静态个人码更实用。

### 4.13 反馈页与单词本页的布局调整

#### 反馈页：二维码位置与两侧留白

原实现用 `justify-content: center` 把二维码卡片推到屏幕垂直中线,
实测卡片顶距导航栏底 **378rpx**,下方留出大片空白。二维码本身也显得
「没有留白」—— 因为图片自带的白色静区(quiet zone,识别必需不能裁)
落在白卡片上完全看不见。

三个改动:

| 项 | 做法 | 原因 |
|----|------|------|
| 位置靠上 | 去掉 `justify-content:center`,改为顶部对齐 + `padding-top: 96rpx` | 卡片位置稳定在导航栏下方,不再随内容高度漂移 |
| 卡片离屏幕更远 | 页面 `padding` 左右从 32rpx → **48rpx** | 原来卡片距屏幕边缘只有 25px,视觉上贴边 |
| 二维码两侧留白 | 新增 `.qr-frame` 内衬框(`padding: 28rpx`,背景白色) | 用容器 padding 把二维码四周撑出空白 |

> **关于内衬框的颜色**:最初用的是浅灰 `#F1F5F9`,想让图片自带的白色静区
> (quiet zone)「显形」,视觉上更清楚地表明二维码两侧有留白。
> 但实际观感是页面里多了一块灰色色块,和整体的蓝色底 + 白卡片不协调,
> 最终改为**纯白** —— 内衬框与卡片融为一体,视觉上是一整块干净白底,
> 留白靠 padding 实际撑出来(而不是靠色块区分)。

**两个必须注意的实现细节**:

1. **`box-sizing: border-box` 必须显式声明**
   小程序 wxss 默认 `content-box`。`.qr-card` 是 `width: 100%` + `padding`,
   不加 border-box 的话实际宽度会超出父容器 56rpx,左右留白完全失效。

2. **`.qr-frame` 必须是 flex 容器**
   `.qr-wrap` 是固定宽度(`420rpx`)的块级元素,父容器不是 flex 时会**左对齐**。
   需要 `display: flex` + `justify-content: center` 才能水平居中。

> 二维码宽度从 480rpx 收到 **420rpx**,给内衬框留出空间,
> 同时保证在 320px 宽的小屏上仍能完整显示。

#### 单词本页:顶部标题栏固定

单词本用 `navigationStyle: custom` 自绘标题栏。原先标题栏是
`position: relative`,跟随 Page 一起滚动 —— 往上滑时标题就消失了。

改成和主页一致的三段式布局:

```
page (overflow:hidden, height:100%)     ← page-meta 的 page-style
└── .notebook-root (flex column, height:100%)
    ├── .notebook-navbar (flex-shrink:0)      ← 固定在视口顶部
    ├── scroll-view.notebook-scroll (flex:1, height:0)   ← 唯一滚动容器
    │   └── .notebook-content (min-height: scrollMinHeight px)
    └── dictation-tab-bar (position:fixed)
```

**标题栏怎么固定**:它不在 `scroll-view` 里,而是 `scroll-view` 的**兄弟节点**。
Page 自身禁止滚动后,唯一能滚的是 `scroll-view`,标题栏自然钉在顶部。

**右上角胶囊按钮**:微信原生控件,在 custom 导航模式下本就固定于右上角,
不随页面滚动。自绘标题栏的高度按胶囊位置计算
(`navBarHeight = (menuButton.top - statusBarHeight) * 2 + menuButton.height`),
两者视觉对齐。

**`min-height` 的两个作用**(和主页同一个机制):

1. iOS 只有 `contentSize > bounds` 才可滚动 → 内容不足一屏就没回弹
2. enhanced 模式下 scroll-view 在「空滚动区域」仍挂载滚动监听并**吞掉
   touch 事件**,子元素 `bindtap` 会失效 —— 单词本记录少的时候,
   「全部记录 / 仅错词」分段控件会点不动

`BOUNCE_EXTRA_RPX = 60`(30px)用 JS 实测容器高度算出,不用百分比
(scroll-view 直接子元素用百分比高度,在部分 WebView 下解析基准不确定)。

### 4.12 主页滚动布局:三段式 + 拖拽事件源

主页是唯一有「长按拖拽排序」的页面,也是唯一需要处理滚动条与固定 Tab 栏冲突的页面。

#### 布局结构

```
page (overflow:hidden, height:100%)     ← page-meta 的 page-style 收敛
└── .dictation-index (flex column, height:100%)
    ├── scroll-view.dictation-scroll (flex:1, height:0)   ← 唯一滚动容器
    │   └── .dictation-content (padding: 8rpx 0 24rpx)
    │       ├── 添加内容卡片
    │       ├── 听写清单卡片
    │       ├── 听写设置卡片
    │       ├── 开始听写按钮
    │       └── 问题反馈入口
    └── dictation-tab-bar (position:fixed)   ← 兄弟节点,不与内容重叠
```

#### 为什么要三段式

| 问题 | 原因 | 解法 |
|------|------|------|
| 滚动条压住 Tab 栏 | Tab 栏 `position:fixed`,滚动条画在最上层 | 改用 scroll-view 独立滚动,滚动条落在内容区,止于 Tab 栏上沿 |
| 底部大片空白 | 全局 `.has-tab-bar` 的 246rpx 里含「主按钮 96rpx」,但主按钮在内容流里,滚到底时本就在 Tab 栏正上方,不该重复预留 | 主页改 flex 布局,Tab 栏是兄弟节点不重叠,只需 24rpx 视觉余量;全局 `.has-tab-bar` 改为 150rpx(单词本页没有主按钮) |

#### 回弹(iOS 弹性)

`bounces` **必须同时开 `enhanced`** 才生效,单独设无效:

```xml
<scroll-view scroll-y="{{ !dragId }}"
             enhanced="{{ true }}"
             bounces="{{ true }}"
             fast-deceleration="{{ true }}"
             enable-back-to-top="{{ true }}">
```

`enable-back-to-top` 让 iOS 点顶部状态栏可回顶部(2.27.3+)。

#### 拖拽事件源:为什么不能用 catchtouchmove

`enhanced` 模式下 scroll-view 会接管 touch 事件,列表项上的 `catchtouchmove` **收不到事件**,
拖拽会失效。而用普通 `bindtouchmove` 又挡不住「排序没落下来页面先滚走」。

社区标准做法是**拖拽期间关掉滚动**:

```xml
scroll-y="{{ !dragId }}"    ← dragId 有值时滚动关闭
```

配合 scroll-view 官方的拖拽事件(需 enhanced):

| 事件 | 用途 |
|------|------|
| `bindlongpress`(列表项) | 长按激活,记录起点 `_dragStartY` / `_dragStartIndex` / `_orderIds` |
| `binddragstart`(scroll-view) | 拖动开始,重新校准起点(长按后手指已移动一点) |
| `binddragging`(scroll-view) | 拖拽中,按 `_dragStartY` 差值算目标索引 |
| `binddragend`(scroll-view) | 松手,按 `_orderIds` 真正重排并持久化 |

**`catchtouchmove` 还有一个副作用**:它会阻止手势冒泡,导致「在列表项上滑动时列表不滚动」。
词条少时可见区域大部分是卡片(能滚),词条一多、可见区域几乎全是列表项 → **用户滑不动、滑不到顶部**。
这是本项目踩过的坑,现方案已彻底移除该绑定。

#### 空清单时的回弹

iOS 的 UIScrollView **只有 contentSize > bounds 时才可滚动**,内容不足一屏就没有回弹。
小程序 scroll-view 同理 —— 而且更糟:社区实测在「空滚动区域」时,
渲染引擎仍会挂载滚动监听逻辑并**吞掉 touch 事件**(伪激活陷阱),
连 `bindtap` 都收不到。

解法:让内容区**永远比容器高一点**,这样恒定可拉可弹。

```js
const BOUNCE_EXTRA_RPX = 60    // ≈ 30px，够拉出弹性即可（见下方「底部间距」说明）

_measureScrollMinHeight() {
  wx.createSelectorQuery().in(this)
    .select('.dictation-scroll')
    .boundingClientRect(rect => {
      const extraPx = BOUNCE_EXTRA_RPX * this._windowWidth / 750
      this.setData({ scrollMinHeight: Math.round(rect.height + extraPx) })
    })
    .exec()
}
```

```xml
<view class="dictation-content" style="min-height: {{ scrollMinHeight }}px;">
```

用 JS 实测而不是写百分比:scroll-view 的直接子元素用百分比高度,
在部分 WebView 下解析基准不确定,实测值最可靠。

#### 底部间距:不要用悬浮按钮

词条多时「开始听写」按钮会被推到视野外。**曾经用「滚到底出现悬浮按钮」解决,
但那个方案是错的**,踩了两个坑:

|坑 | 现象 | 根因 |
|----|------|------|
| 重复按钮 | 滚到底时同时看到内容流里的按钮和悬浮按钮 | 悬浮按钮与主按钮同时可见 |
| 空清单时凭空出现 | 一个词都没加,底部也有个「开始听写」按钮 | `min-height` 让内容**恒定溢出** → `scrolltolower` 必然触发 |

正确做法:**按普通完整页处理** —— 内容多就往下滚,底部留足间距。

```css
.dictation-content {
  padding-bottom: calc(190rpx + env(safe-area-inset-bottom));
}
```

190rpx = Tab 栏可视区 110rpx + 视觉余量 80rpx。Tab 栏是 fixed 在视口底部,
内容滚到底时最后一行会滑到它下面,必须留出这段高度才看得见。

**`min-height` 与 `padding-bottom` 是两套独立机制**:
`min-height` 撑起的是内容整体高度,`padding-bottom` 是内容下方的留白。
两者叠加会让空清单时底部出现大片空白 —— 所以 `BOUNCE_EXTRA_RPX` 要保持小值(60rpx),
只够拉出一点弹性。

#### 关键实现细节

| 细节 | 说明 |
|------|------|
| 根节点 `height:100%` 而非 `100vh` | 100vh 含状态栏+导航栏,会把 Tab 栏顶到屏幕外 |
| 根节点**不用** `position:fixed` | fixed 根节点在部分场景下会让 scroll-view 滚动位置计算异常(滑不到顶部) |
| `scroll-view` 用 `flex:1; height:0` | 只写 `flex:1` 时初始高度是内容高度,flex 压缩不生效 → 不滚动 |
| `page-meta page-style="overflow:hidden; height:100%"` | 禁掉 Page 自身滚动避免双滚动条,并把 page 高度收敛到内容区 |
| 拖拽有**两条事件通路** | A. 列表项 `bindtouchmove`/`bindtouchend`(能冒泡,列表项上也能滑动)<br>B. scroll-view `binddragging`/`binddragend`(enhanced 专属)<br>两者共用 `_applyDrag()` / `_finishDrag()`,保证不叠加位移 |
| `onDragMove` / `onTouchMove` / `onDragEnd` / `_finishDrag` 都要 `dragId` 守卫 | 普通滚动时这些事件也会触发,没守卫会持续 setData / 误持久化 |
| `_touchClientY(e)` 取手指坐标 | enhanced 下各端暴露字段不一致,依次尝试 `touches` → `changedTouches`,取不到返回 null 不做错误推断 |

## 5. 全局状态(`app.globalData`)

MVP 阶段用 `app.globalData` 做跨页面状态传递,简单可靠:

```js
// app.js
App({
  globalData: {
    openid: '',                  // 用户 openid(首次登录后填充)

    // 当前正在进行的听写
    currentDictation: null,      // { list, readCount, interval } 或 null

    // 最近一次判分结果(从判分页传到结果页)
    currentResult: null,         // { score, items } 或 null

    // OCR 识别结果(从拍照页传到确认页)
    pendingOcrResult: null       // { items: [...] } 或 null
  }
})
```

### 5.1 为什么不用全局 store(Redux/Mobx)?

- MVP 数据流简单,page 之间只通过 globalData 传递几个对象,不需要复杂 store
- 永久数据(单词本历史)走云数据库,不存内存

### 5.2 globalData 生命周期

- 进入听写工具时填充 → 离开时不主动清除(下次进入会被新数据覆盖)
- 小程序冷启动时全部为初始值

## 6. 自定义底部 Tab(听写工具内)

### 6.1 为什么不用 `tabBar`?

- 微信原生 `tabBar` 是**全局配置**,会出现在所有页面
- 我们只想让它在听写工具内出现(首页、判分页、单词本等)
- 所以用自定义组件实现

### 6.2 组件设计

`components/tab-bar/index.wxml`:

```html
<view class="tab-bar">
  <view class="tab-item {{ active === 'dictation' ? 'active' : '' }}" bindtap="switchTab" data-tab="dictation">
    <icon name="volume" />
    <text>听写</text>
  </view>
  <view class="tab-item {{ active === 'notebook' ? 'active' : '' }}" bindtap="switchTab" data-tab="notebook">
    <icon name="book" />
    <text>单词本</text>
  </view>
</view>
```

`components/tab-bar/index.js`:

```js
Component({
  properties: {
    active: { type: String, value: 'dictation' }
  },
  methods: {
    switchTab(e) {
      const tab = e.currentTarget.dataset.tab
      if (tab === this.data.active) return
      const url = tab === 'dictation'
        ? '/pages/dictation/index/index'
        : '/pages/dictation/notebook/index'
      wx.redirectTo({ url })
    }
  }
})
```

### 6.3 哪些页面要展示 Tab

| 页面 | 展示 Tab? |
|---|---|
| ① ② 听写主页 | ✅ 高亮"听写" |
| ⑨ 单词本 | ✅ 高亮"单词本" |
| 其他(③④⑤⑥⑦⑧) | ❌ 不展示(都是流程中的页面) |
