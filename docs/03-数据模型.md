# 书斋小程序 · 数据模型

> 给开发者(包括 Claude Code)看的数据库设计。用**微信云开发的云数据库**实现。

---

## 1. 数据库总览

云数据库共 **2 个集合**(MVP 阶段):

| 集合名 | 用途 | 单条大约大小 |
|---|---|---|
| `users` | 用户表(记录 openid + 基本信息) | ~200B |
| `sessions` | 听写会话表(一次听写的完整记录) | ~2-5 KB |

> 不需要额外的"单词本"表 —— 单词本就是 `sessions` 的聚合视图。

---

## 2. `users` 集合

### 2.1 用途

记录每个 openid 对应的用户信息。**首次使用时自动创建**,后续读取不更新。

### 2.2 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | string | 自动 | 云数据库自动生成 |
| `_openid` | string | ✅ | 微信用户 openid(云开发自动注入) |
| `createdAt` | server date | ✅ | 首次进入时间 |
| `lastActiveAt` | server date | ✅ | 最近一次进入时间 |

### 2.3 索引

| 字段 | 类型 | 说明 |
|---|---|---|
| `_openid` | 唯一索引 | 加速按 openid 查询 |

### 2.4 权限设置(云开发后台)

| 权限 | 设置 |
|---|---|
| 读 | **仅创建者可读** |
| 写 | **仅创建者可写** |

---

## 3. `sessions` 集合

### 3.1 用途

每完成一次听写(进入判分结果页那一刻),写入一条记录。这就是**单词本的数据来源**。

### 3.2 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `_id` | string | 自动 | 云数据库自动生成 |
| `_openid` | string | ✅ | 用户 openid(自动注入) |
| `createdAt` | server date | ✅ | 完成时间 |
| `mode` | string | ✅ | 判分方式:`'ocr'` 或 `'manual'` |
| `settings` | object | ✅ | 当时的听写设置 |
| `score` | object | ✅ | 得分总结 |
| `items` | array | ✅ | 每个条目的明细 |

#### 3.2.1 `settings` 子对象

```js
{
  readCount: 2,       // 朗读次数
  interval: 5         // 间隔秒数
}
```

#### 3.2.2 `score` 子对象

```js
{
  correct: 4,         // 答对数量
  total: 6,           // 总数
  rate: 0.67          // 正确率(0-1)
}
```

#### 3.2.3 `items` 数组的每项

```js
{
  // ── 标准答案 ──
  content: 'apple',              // 原始内容
  type: 'en_word',               // 'en_word' | 'cn_word' | 'en_sentence' | 'cn_sentence'

  // ── 用户答案 ──
  userAnswer: 'oraneg',          // OCR 识别或手动核对结果;manual 模式下为 null
  isCorrect: false,              // 是否正确

  // ── 错误详情(仅 isCorrect=false 且为英文句子时) ──
  wordDiff: [                    // 词级 diff,可选字段
    { word: 'I',      ok: true },
    { word: 'like',   ok: true },
    { word: 'aples',  ok: false, expected: 'apples' },
    { word: 'very',   ok: true },
    { word: 'much',   ok: true }
  ]
}
```

### 3.3 完整示例(一条 session)

```js
{
  _id: "abc123...",
  _openid: "oXX...",
  createdAt: ISODate("2026-05-16T10:30:00Z"),
  mode: "ocr",
  settings: {
    readCount: 2,
    interval: 5
  },
  score: {
    correct: 4,
    total: 6,
    rate: 0.67
  },
  items: [
    { content: "apple", type: "en_word", userAnswer: "apple", isCorrect: true },
    { content: "苹果", type: "cn_word", userAnswer: "苹果", isCorrect: true },
    { content: "orange", type: "en_word", userAnswer: "oraneg", isCorrect: false },
    {
      content: "I like apples very much.",
      type: "en_sentence",
      userAnswer: "I like aples very much",
      isCorrect: false,
      wordDiff: [
        { word: "I", ok: true },
        { word: "like", ok: true },
        { word: "aples", ok: false, expected: "apples" },
        { word: "very", ok: true },
        { word: "much", ok: true }
      ]
    },
    { content: "床前明月光,疑是地上霜。", type: "cn_sentence", userAnswer: "床前明月光疑是地上霜", isCorrect: true },
    { content: "grape", type: "en_word", userAnswer: "grape", isCorrect: true }
  ]
}
```

### 3.4 索引

| 字段 | 类型 | 说明 |
|---|---|---|
| `_openid` | 普通索引 | 加速按用户查询 |
| `createdAt` | 普通索引 | 加速按时间排序 |

### 3.5 权限设置

| 权限 | 设置 |
|---|---|
| 读 | **仅创建者可读** |
| 写 | **仅创建者可写** |

## 4. 单词本数据获取

### 4.1 全部记录(按时间倒序)

```js
db.collection('sessions')
  .where({ _openid: '{openid}' })
  .orderBy('createdAt', 'desc')
  .limit(20)              // 分页,每次 20 条
  .get()
```

### 4.2 仅错词(从所有 sessions 中提取错的条目)

云开发的数据库不支持对 array 内部的元素做 where 过滤,所以**在前端做**:

```js
// 1. 拉取所有 sessions
const { data: sessions } = await db.collection('sessions')
  .where({ _openid: '{openid}' })
  .orderBy('createdAt', 'desc')
  .limit(50)
  .get()

// 2. 前端筛错词
const wrongItems = []
for (const session of sessions) {
  for (const item of session.items) {
    if (!item.isCorrect) {
      wrongItems.push({
        ...item,
        sessionDate: session.createdAt
      })
    }
  }
}
```

### 4.3 性能考虑

- MVP 阶段每个用户的 sessions 一般不超过 100 条,前端处理够快
- 如果未来某用户数据量大,**考虑加分页 / 时间窗口限制**(比如只看最近 90 天)

## 5. 本地缓存(`wx.setStorage`)

有些数据不必每次都查云数据库,本地存一份:

### 5.1 缓存项清单

| key | 类型 | 用途 | 失效策略 |
|---|---|---|---|
| `openid` | string | 用户 openid | 永不失效(冷启动重新登录会覆盖) |
| `settings` | object | 用户上次的听写设置 | 永久,跨会话保留 |
| `pendingList` | array | 还没开始听写的清单(未完成关闭) | 进入听写后清除 |

### 5.2 settings 缓存示例

```js
// 用户调整朗读次数和间隔时
wx.setStorageSync('settings', { readCount: 3, interval: 8 })

// 主页加载时
const settings = wx.getStorageSync('settings') || { readCount: 2, interval: 5 }
```

### 5.3 pendingList(待听写清单)缓存

避免用户输入了一半就退出,下次进来又得重新输:

```js
// 添加内容后
wx.setStorageSync('pendingList', currentList)

// 主页加载时
const pendingList = wx.getStorageSync('pendingList') || []
```

听写完成后清除:

```js
wx.removeStorageSync('pendingList')
```

## 6. 数据流总览图

```
                  用户在主页输入/拍照
                          │
                          ▼
                  [本地缓存 pendingList]
                          │
                          ▼
                  开始听写 → 听写完成
                          │
                ┌─────────┴─────────┐
            拍照判分           手动核对
                │                  │
                ▼                  │
        [云函数 ocr 转发]           │
        [拿到 OCR 结果]            │
                │                  │
                └────────┬─────────┘
                         ▼
                  [前端做规范化匹配 + 词级 diff]
                         │
                         ▼
                  生成 session 对象
                         │
                         ▼
                  [写入云数据库 sessions]
                         │
                         ▼
                  跳转到判分结果页 ⑦
                         │
                         ▼
                  用户切到单词本 Tab
                         │
                         ▼
                  [从云数据库读 sessions]
                         │
                         ▼
                  按日期分组展示
```

## 7. 数据安全与合规

### 7.1 用户隐私

- **不收集**任何个人敏感信息(姓名、年龄、电话等)
- 仅用 openid 作为用户标识(微信生态内,符合规范)
- 听写内容是用户主动录入的,默认归属于该用户

### 7.2 数据清除

- MVP 阶段**不提供**主动清除入口(用户量小,需求低)
- 后续可在"我的"页面加"清空所有听写记录"按钮(等加个人中心时)

### 7.3 数据导出

- MVP 阶段**不提供**数据导出
- 后续视情况补"导出单词本到 Excel"等功能

## 8. 数据迁移与扩展性

### 8.1 当前结构如何应对未来需求?

| 需求 | 怎么扩展 |
|---|---|
| 加单词释义 | 在 `items[i]` 加 `meaning` 字段 |
| 加错题智能复习 | 新增 `wrong_items` 集合,从 sessions 提取 + 加复习状态 |
| 加分享成绩 | 把 session 设为可分享,加 `shareToken` 字段 |
| 加家庭共享 | 加 `familyId` 字段,改权限规则 |

### 8.2 别现在过度设计

MVP 阶段**严格只用 2 个集合 + 6 个全局字段**。所有"以后可能要"的字段都不要现在加,YAGNI 原则。
